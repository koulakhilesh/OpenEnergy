# OpenEnergy v2.0 — Design

Status: approved · Branch: `release/v2.0` · Tag: `v2.0.0`

v2.0 is a clean break from the 1.x scripts. It rebuilds OpenEnergy as an installable
package with a correct, tested battery-arbitrage backtester. Later releases build on it:

| Release | Scope |
|---------|-------|
| v2.0 | Foundation: packaging, data layer, battery physics, dispatch, backtesting, CLI, docs |
| v2.1 | PV and wind assets, captured price, co-located storage |
| v2.2 | Net load, curtailment, storage sizing, emissions |
| v3.0 | System dispatch (merit order, conventional generation) via a PyPSA adapter |

Numbering continues from the existing `v1.6.4` tag.

## Goals

- Answer "what would this battery have earned, and why?" reproducibly from a YAML scenario.
- Separate planning (forecast prices) from settlement (actual prices) so results carry no lookahead.
- Report results against a perfect-foresight benchmark.
- Stay small: pandas, numpy, HiGHS, pydantic, typer. Heavy ML is an optional extra.

## Non-goals (v2.0)

Intraday markets, ancillary services, network constraints, multi-asset portfolios,
PV/wind modelling, and a web API.

## Package layout

```
src/openenergy/
  errors.py      OpenEnergyError, ConfigError, DataError, DispatchError, InfeasibleDispatchError
  data/          PriceSeries validation, OPSD CSV source, missing-data policy
  assets/        BatterySpec, BatteryState, apply_dispatch, degradation
  forecast/      Forecaster protocol: PerfectForesight, NaiveLastWeek, NoisyForesight; ML extra
  dispatch/      arbitrage MILP and solver selection
  backtest/      rolling-horizon engine
  metrics/       P&L, captured spread, cycles, capture ratio, forecast error
  scenario.py    pydantic models loaded from YAML
  cli.py         typer app: run, compare, data info, forecast train
```

## Conventions

- Time: tz-aware UTC `DatetimeIndex`, fixed step `Δt` (hours) inferred and validated.
  A timestamp labels the start of its interval.
- Units: power MW, energy MWh, price currency/MWh. Currency is carried as metadata
  (OPSD `GB_GBN` is GBP; other zones are EUR).
- Errors: domain exceptions, never `assert` for runtime validation, never swallowed.
- Logging: stdlib `logging.getLogger(__name__)`; the CLI configures handlers.

## Battery physics

`BatterySpec` (immutable): `power_mw`, `energy_mwh`, `eta_charge`, `eta_discharge`,
`soc_min`, `soc_max` (fractions of usable energy), `initial_soc`, degradation parameters.

`BatteryState`: `energy_mwh` stored, `soh` (state of health), `throughput_mwh`,
`equivalent_cycles`.

Settlement applies a pure transition per interval:

$$E_{t+1} = E_t + \eta_c c_t \Delta t - \frac{d_t \Delta t}{\eta_d}$$

- Throughput and equivalent full cycles accumulate only the interval's own energy:
  $\Delta N = (c_t + d_t)\Delta t / (2 E_{rated})$.
- Degradation: linear cycle fade per equivalent cycle plus calendar fade per year,
  computed from lifetime totals so it never compounds; usable energy is
  $E_{rated} \cdot SOH$. Applied at day boundaries.
- Temperature derating is deferred until a temperature input exists (not in OPSD).
- Requests outside power or SOC limits raise `DispatchError` rather than being clipped silently.

## Dispatch model

Daily MILP solved with HiGHS (`highspy`); GLPK is not required.

$$\max \sum_t \hat p_t (d_t - c_t)\Delta t - \kappa \sum_t (c_t + d_t)\Delta t$$

subject to, for $t = 0..T-1$ with states $E_0..E_T$:

- $E_{t+1} = E_t + \eta_c c_t \Delta t - d_t \Delta t / \eta_d$, $E_0$ fixed
- $0 \le c_t \le P u_t$, $0 \le d_t \le P (1 - u_t)$, $u_t \in \{0,1\}$
- $SOC_{min} E_{usable} \le E_t \le SOC_{max} E_{usable}$
- end-of-day target $E_T \ge E_{target}$ (default: initial energy)
- optional daily cycle cap $\sum_t (c_t + d_t)\Delta t \le 2 N_{max} E_{usable}$

$\kappa$ is an optional degradation cost per MWh throughput. The binary prevents
simultaneous charge and discharge, which an LP would exploit at negative prices.
Infeasibility raises `InfeasibleDispatchError` with the day and constraint context.

## Backtest timing

For each day $D$:

1. The forecaster receives prices strictly before the decision time
   (default: 12:00 UTC on $D-1$, day-ahead gate closure).
2. The optimiser plans day $D$ on forecast prices.
3. Settlement applies the plan through the physics model and values it at actual prices.
4. State carries to $D+1$.

Every run also executes the perfect-foresight benchmark on the same days.

## Forecasters

- `PerfectForesight`: actual prices (benchmark).
- `NaiveLastWeek`: same interval seven days earlier, falling back to fourteen.
- `NoisyForesight`: actual prices plus seeded Gaussian error of a chosen spread, to
  measure how revenue degrades with forecast error. Replaces the 1.x sine-envelope
  "simulated" prices, which ignored the market.
- Forecasters receive only history before the decision time; `NaiveLastWeek` rejects
  history that extends into the forecast window.
- `openenergy[forecast]`: gradient-boosted model with chronological train/validation
  splits and saved metadata (features, training window, metrics). Artifacts are produced
  by `openenergy forecast train` and never committed.

## Data

`OPSDCsvSource` reads the bundled OPSD 60-minute extract (2015 to mid-2020).
Validation checks index type, monotonicity, duplicates, frequency and expected columns.
Price gaps up to `max_gap_hours` (default 2) are linearly interpolated; days with larger
gaps are skipped and listed in the run report.

Attribution: Open Power System Data. 2020. Data Package Time series. Version 2020-10-06.
https://doi.org/10.25832/time_series/2020-10-06. Primary data from ENTSO-E Transparency
and other sources listed at the URL.

## Scenarios and CLI

```yaml
name: gb-2h-2019
data: {source: opsd, zone: GB_GBN, start: 2019-01-01, end: 2019-12-31}
battery: {power_mw: 1, energy_mwh: 2, eta_charge: 0.95, eta_discharge: 0.95}
forecast: naive_last_week
dispatch: {solver: highs, end_soc: initial, degradation_cost: 5}
```

- `openenergy run scenario.yaml` prints a summary and writes `intervals.csv`,
  `daily.csv` and `summary.json` to the output directory.
- `openenergy compare a.yaml b.yaml` ranks scenarios on the same metrics.
- `openenergy data info` describes available zones, ranges and gaps.

## Metrics

Net P&L, P&L per MW-year, captured spread (currency/MWh discharged), equivalent cycles,
final SOH, capture ratio (realised / perfect-foresight P&L), forecast MAE and RMSE.

## Testing

- Physics invariants: energy balance, cycle accounting, limit violations.
- Dispatch: small cases with hand-computed optima, negative prices, infeasible targets.
- Backtest: perfect foresight equals the per-day optimum; no lookahead in forecasters.
- CLI smoke test; OPSD golden week with fixed expected P&L.
- CI: uv, ruff, mypy, pytest on Python 3.14 (the minimum supported version).

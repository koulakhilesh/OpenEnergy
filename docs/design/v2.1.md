# OpenEnergy v2.1 — Design

Status: released · Tag: `v2.1.0`

v2.1 adds renewable generation to the v2.0 battery backtester: PV and wind assets, the
price they capture, and batteries co-located with them behind a shared grid connection.

## Goals

- Measure how solar and wind are valued by the market: captured price, capture rate and
  their trend over time (cannibalisation).
- Quantify the value of co-locating a battery with a renewable plant against running the
  two separately.
- Keep v2.0 scenarios working unchanged.

## Non-goals (v2.1)

Weather-driven generation models (no wind speed or irradiance data yet), generation
forecasting, network constraints beyond a single connection limit, multi-site portfolios.

## Data

OPSD provides GB capacity-factor profiles (`GB_GBN_{tech}_profile`, generation divided by
installed capacity) for `solar`, `wind`, `wind_onshore` and `wind_offshore`, hourly from
2015 to 30 December 2019. Capacity is missing after 2019, so profiles end there.

- `OPSDCsvSource.profile(zone, technology, start, end)` returns a `ProfileSeries` on the
  same validated UTC grid as prices.
- Profiles are clipped to [0, 1]; the number of clipped intervals is reported. The solar
  profile exceeds 1.0 in 233 hours (up to 1.367) because reported capacity lags new
  build, which also biases solar capacity factors upward (15–18% against about 11%
  expected for GB). This is documented, not corrected.
- Short gaps are interpolated with the same `max_gap_hours` policy as prices.

## Renewable asset

`RenewableSpec`: `technology`, `capacity_mw`, `degradation_per_year` (fraction, applied
as $(1 - r)^{years}$, the convention for PV).

$$g_t = C \cdot cf_t \cdot (1 - r)^{\text{age}}$$

## Capture metrics

For generation $g_t$ (MWh per interval) and price $p_t$:

- Captured price: $\bar p_{cap} = \sum_t p_t g_t / \sum_t g_t$
- Baseload (time-weighted) price: $\bar p = \frac{1}{T}\sum_t p_t$
- Capture rate: $\bar p_{cap} / \bar p$
- Capacity factor, energy generated at negative prices, and market revenue.

`openenergy capture DATA [--zone] [--technology]` prints these by calendar year, so the
cannibalisation trend is one command.

## Co-located dispatch

One daily MILP for a renewable plant with available output $G_t$, a battery, and a grid
connection with export limit $X$ and import limit $I$ (0 disables grid charging):

- $G_t = y_t + s_t + k_t$: output to grid $y_t$, to battery $s_t$, curtailed $k_t$
- battery charge $c_t = s_t + m_t$, with grid import $m_t \le I$
- net export $x_t = y_t + d_t - m_t$, with $-I \le x_t \le X$
- battery constraints as in v2.0 (binary prevents simultaneous charge and discharge)

Objective, with an optional premium $\pi$ per MWh generated and delivered (ROC- or
CfD-like support):

$$\max \sum_t \left[\hat p_t\, x_t + \pi\,(y_t + s_t)\right]\Delta t - \kappa \sum_t (c_t + d_t)\,\Delta t$$

Curtailment then emerges when prices fall below $-\pi$ or the connection is full.

**Benchmark:** the same plant and battery operated separately (plant exports all output up
to its own capacity; battery is a standalone v2.0 asset with its own connection). The
difference is the co-location value.

**Forecast limitation:** v2.1 plans with actual renewable output (perfect generation
foresight) and forecast prices. Co-location results are therefore an upper bound; this is
stated in outputs and docs. Generation forecasting is future work.

## Scenarios

New optional sections; battery-only v2.0 scenarios are unchanged.

```yaml
assets:
  pv: {capacity_mw: 10, degradation_per_year: 0.005}
battery: {power_mw: 5, energy_mwh: 10}
grid: {export_limit_mw: 10, import_limit_mw: 10, premium_per_mwh: 0}
```

`technology` defaults by key (`pv` → `solar`, `wind` → `wind`); `wind` may set
`technology: wind_offshore`. Outputs gain plant columns (available, exported, to battery,
curtailed) and capture metrics.

## Testing

- Profile loading, clipping and gap filling; technology/zone errors.
- Capture metrics on hand-computed series.
- Co-location MILP: export limit clipping recaptured by the battery; curtailment below
  $-\pi$; no grid charging when $I = 0$; reduces to the v2.0 battery model with no plant.
- Co-located backtest equals or beats the separate benchmark under perfect foresight.
- CLI smoke tests for `capture` and a co-located `run`.

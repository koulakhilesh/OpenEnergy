    API reference¶

    Data¶

    openenergy.data.series ¶

    Validated time series (prices, capacity factors) on a regular UTC grid.

    PriceSeries dataclass ¶

    Prices in currency/MWh, each timestamp labelling the start of its interval.

    between ¶

    between(start=None, end=None)

    Return the whole UTC days from start to end, both inclusive.

    day ¶

    day(day)

    Return the prices for one UTC day; the day must be fully covered.

    complete_days ¶

    complete_days()

    UTC days with every interval present and no missing prices.

    ProfileSeries dataclass ¶

    Capacity factors in [0, 1] for one technology; clipped counts values capped on load.

    between ¶

    between(start=None, end=None)

    Return the whole UTC days from start to end, both inclusive.

    day ¶

    day(day)

    Return the capacity factors for one UTC day; the day must be fully covered.

    complete_days ¶

    complete_days()

    UTC days with every interval present and no missing values.

    fill_gaps ¶

    fill_gaps(
    series: PriceSeries, max_gap_hours: float
) -> tuple[PriceSeries, int]

    fill_gaps(
    series: ProfileSeries, max_gap_hours: float
) -> tuple[ProfileSeries, int]

    fill_gaps(
    series: IntensitySeries, max_gap_hours: float
) -> tuple[IntensitySeries, int]

    fill_gaps(series, max_gap_hours)

    Linearly interpolate interior gaps no longer than max_gap_hours.

    Returns the filled series and the number of intervals filled.

    openenergy.data.opsd ¶

    Open Power System Data (OPSD) time-series CSV source.

    OPSDCsvSource ¶

    Reads day-ahead prices and capacity-factor profiles from an OPSD singleindex CSV.

    zones ¶

    zones()

    Bidding zones with a day-ahead price column.

    technologies ¶

    technologies(zone)

    Technologies with a capacity-factor profile for zone.

    prices ¶

    prices(zone, start=None, end=None)

    Day-ahead prices for zone over whole UTC days, start and end inclusive.

    profile ¶

    profile(zone, technology, start=None, end=None)

    Capacity factors for technology in zone, capped to [0, 1].

    series ¶

    series(column, start=None, end=None)

    Any column as a validated series over whole UTC days, start and end inclusive.

    load ¶

    load(zone, start=None, end=None)

    Actual load in MW (ENTSO-E Transparency).

    generation ¶

    generation(zone, technology, start=None, end=None)

    Actual generation in MW for technology (e.g. solar, wind).

    openenergy.data.ember ¶

    GB hourly day-ahead prices from Ember, converted to GBP with ECB reference rates.

    EmberPriceSource ¶

    Reads gb_day_ahead_ember.csv and ecb_gbp_per_eur.csv written by the fetch script.

    rates defaults to ecb_gbp_per_eur.csv next to the price file.

    prices ¶

    prices(zone='GB_GBN', start=None, end=None)

    Hourly GBP/MWh over whole UTC days, start and end inclusive.

    gb_prices ¶

    gb_prices(paths, start, end)

    GB hourly day-ahead prices from OPSD and/or Ember files, earlier files taking priority.

    Each file's type is read from its header. A later file only adds hours outside the span already covered, never filling gaps inside it (Ember interpolates its own gaps). Returns the prices and the attribution of every file that supplied at least one value.

    openenergy.data.update ¶

    Download the latest GB day-ahead prices (Ember), ECB GBP rates and forecast inputs.

    cache_dir ¶

    cache_dir()

    $XDG_CACHE_HOME/openenergy/prices, defaulting to ~/.cache/openenergy/prices.

    update_prices ¶

    update_prices(directory)

    Write Ember hourly UK prices (EUR, unchanged) and ECB daily GBP rates to directory.

    Returns the price file, its number of hours and the first and last UTC hour.

    update_fundamentals ¶

    update_fundamentals(directory, end=None)

    Write the daily gas price, NESO's day-ahead demand forecast and Elexon's wind forecast.

    Returns (file name, rows, first, last) for each file written.

    openenergy.data.carbon ¶

    GB carbon intensity from NESO's Carbon Intensity API extract.

    IntensitySeries dataclass ¶

    Average grid carbon intensity in gCO2/kWh (= kg/MWh).

    rejected counts values outside [0, 1000] that were treated as missing.

    CarbonIntensitySource ¶

    Reads utc_timestamp, forecast, actual half-hourly CSVs written by the fetch script.

    intensity ¶

    intensity(kind='actual', start=None, end=None, step=None)

    Intensity over whole UTC days, optionally averaged to a coarser step.

    An averaged interval is missing unless every half-hour in it is present.

    openenergy.data.neso ¶

    GB half-hourly generation by fuel from NESO's historic generation mix extract.

    GenerationMixSource ¶

    Reads the utc_timestamp, <fuels>, generation CSV written by the fetch script.

    mix ¶

    mix(start=None, end=None, step=None)

    Generation by fuel and in total (MW) over whole UTC days, start/end inclusive.

    Averaging to a coarser step leaves an interval missing unless every half-hour in it is present.

    openenergy.data.response ¶

    GB dynamic frequency response (DC, DM, DR): auction clearing prices and utilisation.

    Service dataclass ¶

    A response product: low exports when frequency falls, high imports when it rises.

    envelope lists (deviation beyond 50 Hz, fraction of contracted MW) points after the deadband, from NESO's Response Services Service Terms; delivery is linear between them.

    delivered ¶

    delivered(frequency_hz)

    Fraction of the contracted MW delivered at each frequency sample.

    ResponseMarket dataclass ¶

    Clearing prices (GBP/MW/h) per delivery block and monthly utilisation per service.

    prices is indexed by block start (UTC) with an end column and one column per service; utilisation is indexed by month start (UTC).

    utilisation_at ¶

    utilisation_at(starts)

    Each block's monthly factors; months without frequency data use the overall mean.

    ResponseSource ¶

    Reads the block prices and monthly utilisation CSVs written by the fetch script.

    utilisation ¶

    utilisation(frequency_hz)

    Average delivery per contracted MW (= MWh per MW per hour) over the samples.

    openenergy.data.fleet ¶

    GB fleet capacity, efficiency, fuel prices and carbon prices for the system model.

    SystemInputs ¶

    Reads the system CSVs written by scripts/fetch_system_data.py from one directory.

    gas_price daily uses the System Average Price of gas from fundamentals (default: the fundamentals folder next to directory) from its first day, and DESNZ's quarterly price before; quarterly uses DESNZ's quarterly price throughout.

    unit_parameters ¶

    unit_parameters()

    Unit size (MW), minimum stable output (share) and start cost (GBP/MW) by technology.

    capacity ¶

    capacity(index)

    MW at each timestamp, linear in time between end-of-year values.

    efficiency ¶

    efficiency(year)

    Fleet-average thermal efficiency (gross calorific value) for year.

    A blank value (no station of that type ran) falls back to the latest earlier year.

    fuel_prices ¶

    fuel_prices(index)

    GBP per MWh of fuel at each timestamp.

    Coal and oil (and gas with gas_price: quarterly) come from the quarter the timestamp falls in; blank (suppressed) prices carry forward from the latest earlier quarter. Daily gas applies the gas day's price, carried forward over missing days.

    carbon_prices ¶

    carbon_prices(index)

    ETS price (GBP/t) and carbon price support (GBP/MWh of fuel) at each timestamp.

    Each row applies from its valid_from date (1 April) to the next. The ETS is the EU ETS to 2020 and the UK ETS from 2021; prices in USD or EUR convert at the stored ECB rates. Files with only eu_ets_usd_per_t (v3.1 and earlier) are still read.

    openenergy.data.interconnectors ¶

    GB interconnectors: capacity (NESO register), in-service dates and flows (Elexon), and neighbouring markets' day-ahead prices (Ember).

    Interconnector dataclass ¶

    One GB link: firm import and export capacity (TEC) and the day it entered service.

    in_service comes from the bundled Elexon flows (see IN_SERVICE_DAYS), or is None if the link was already in service when the record starts. import_availability and export_availability are the shares of a price taker's trade the link actually made (availability_from_flows); 1 when no fitted file is present.

    NeighbourPriceSource ¶

    Reads europe_day_ahead_ember.csv (EUR/MWh) and converts with the ECB rate file.

    prices ¶

    prices(neighbour, index, max_gap_hours=3)

    GBP/MWh on index; gaps up to max_gap_hours are interpolated.

    interconnectors ¶

    interconnectors(system_dir)

    Built links from interconnectors.csv with in-service dates from the flow record, and their availability from interconnector_availability.csv when present.

    availability_from_flows ¶

    availability_from_flows(system_dir, gb_prices, neighbours)

    Per link, the share of a price taker's imports and exports that actually flowed.

    A price taker on gb_prices (actual hourly GBP/MWh, the fitting years) imports at full capacity whenever GB is dearer than the neighbour and exports whenever it is cheaper, from the day the link entered service. Each share is the actual energy (Elexon) over that trade, at most 1. Modelled prices are never used. Links with no trade in the period get the mean of the others.

    availability_by_gap ¶

    availability_by_gap(system_dir, gb_prices, neighbours)

    Per link and direction, the share of capacity used by size of the price gap.

    Hours from the day each link entered service are binned by the gap between gb_prices (actual hourly GBP/MWh) and the neighbour's actual price, from the lower edges in GAP_EDGES: imports when GB is dearer, exports when cheaper. Each bin's share is the link's mean hourly flow that way (Elexon, hourly) over its capacity, made non-decreasing in the gap (weighted by hours) so that it can be offered as stepped capacity. Bins without hours take their neighbour's share. Modelled prices are never used. Columns: link, direction, gap_from, share, hours.

    gap_shares ¶

    gap_shares(system_dir)

    Import and export shares per gap bin (GAP_EDGES) from GAP_FILE.

    interconnector_flows_hourly ¶

    interconnector_flows_hourly(system_dir)

    Hourly net flow per link from 2019, MW (positive into GB), columns <fuel type>_mw.

    interconnector_flows ¶

    interconnector_flows(system_dir)

    Daily MWh per link, columns <fuel type>_import_mwh and _export_mwh.

    openenergy.data.fes ¶

    NESO Future Energy Scenarios: capacity, storage and demand by pathway and year.

    FesSource ¶

    Reads the ES1 and ED1 tables written by scripts/fetch_fes.py (unchanged).

    capacity_mw ¶

    capacity_mw(pathway, year)

    Installed capacity (MW) by FES technology type, all connections summed.

    storage_gwh ¶

    storage_gwh(pathway, year)

    Storage energy capacity (GWh) by FES technology type.

    demand_gwh ¶

    demand_gwh(pathway, year)

    Annual GB system demand (GWh, fiscal year).

    years ¶

    years(pathway)

    Years with capacity data for the pathway.

    supply ¶

    supply(pathway, year, variable)

    Any ES1 variable (e.g. Export (TWh)) summed by technology type.

    openenergy.data.quality ¶

    Transparent filters for telemetry glitches in metered time series.

    flag_glitches ¶

    flag_glitches(
    values, spike_fraction=0.25, dropout_fraction=0.5
)

    Flag isolated spikes and dropouts in a smooth series such as demand.

    A spike deviates from its centred 5-interval median by more than spike_fraction of the series' 99th percentile; a dropout falls below dropout_fraction of its centred 7-day median. Genuine ramps sit on their rolling median, so are not flagged.

    Assets¶

    openenergy.assets.battery ¶

    Battery specification, state and physics.

    BatteryState dataclass ¶

    Physical state carried between intervals.

    BatterySpec dataclass ¶

    Battery ratings. SOC limits are fractions of usable (degraded) energy.

    DispatchOutcome dataclass ¶

    State after a dispatch and the stored energy at each interval boundary.

    apply_dispatch ¶

    apply_dispatch(
    spec,
    state,
    charge_mw,
    discharge_mw,
    step_hours,
    response_charge_mw=None,
    response_discharge_mw=None,
)

    Apply a charge/discharge schedule (MW per interval) and return the new state.

    response_charge_mw/response_discharge_mw are average power moved by frequency response in each interval; they may overlap (low and high services in one interval).

    age ¶

    age(spec, state, hours)

    Advance calendar age and recompute state of health from lifetime totals.

    openenergy.assets.renewable ¶

    Renewable plants driven by capacity-factor profiles.

    RenewableSpec dataclass ¶

    A plant of capacity_mw whose output declines by degradation_per_year.

    generation_mw ¶

    generation_mw(profile, start_age_years=0.0)

    Available output in MW: capacity x capacity factor x (1 - degradation)^age.

    Age is start_age_years at the first interval of profile and grows with time.

    Dispatch¶

    openenergy.dispatch.arbitrage ¶

    Single-battery energy arbitrage as a mixed-integer linear programme (HiGHS).

    DispatchConfig dataclass ¶

    Optimisation settings.

    end_soc is a fraction of usable energy; None means return to the starting energy. max_cycles caps equivalent full cycles over the horizon (the backtest scales it by the days planned, so it stays a per-day cap). lookahead_days makes the backtest plan each day together with that many following days of forecasts, settling only the first; the end-energy target then applies at the end of the last day.

    DispatchPlan dataclass ¶

    Optimal schedule in MW per interval and stored energy at each boundary (T+1).

    With frequency response, reserve_mw is MW held per block and service, and response_charge_mw/response_discharge_mw the expected average power it moves. expected_revenue covers energy; expected_response the availability payments.

    Reserve dataclass ¶

    Frequency-response options over a horizon.

    block maps each interval to a row of price (-1 where nothing can be reserved). price (GBP/MW/h) and utilisation (MWh delivered per MW per hour) have one row per block and one column per service. fixed holds MW already committed (NaN where free). beyond_hours is how long each block runs past the horizon end; the plan keeps enough energy to stay idle through it. With energy_paid, delivered energy is bought or sold at the interval's price; otherwise it is free, as under NESO's ABSVD adjustment.

    signs ¶

    signs()

    +1 for services that export (low), -1 for those that import (high).

    flows ¶

    flows(reserve_mw)

    Average charge and discharge MW from responding, per interval.

    payment ¶

    payment(reserve_mw, price, step_hours)

    Availability payments for the intervals in the horizon at price per block.

    optimise_dispatch ¶

    optimise_dispatch(
    spec,
    state,
    prices,
    step_hours,
    config=None,
    reserve=None,
)

    Maximise arbitrage (and response) revenue less degradation cost over the horizon.

    energy_window ¶

    energy_window(spec, state, config)

    Stored-energy bounds and the end-of-horizon target, in MWh.

    openenergy.dispatch.colocated ¶

    A renewable plant and a battery behind one grid connection.

    GridConnection dataclass ¶

    Connection limits in MW; premium_per_mwh is paid on renewable output delivered.

    import_limit_mw defaults to the export limit; set it to 0 to forbid grid charging.

    ColocatedPlan dataclass ¶

    Flows in MW per interval; export_mw is net (negative when importing).

    optimise_colocated ¶

    optimise_colocated(
    spec,
    state,
    available_mw,
    prices,
    step_hours,
    grid,
    config=None,
)

    Maximise market revenue plus premium less degradation cost for plant and battery.

    dispatch_plant ¶

    dispatch_plant(available_mw, prices, step_hours, grid)

    A plant on its own: export up to the limit unless price plus premium is negative.

    Forecasting¶

    openenergy.forecast.baseline ¶

    Baseline price forecasters.

    Forecaster ¶

    Bases: Protocol

    Predicts prices for index from history observed before the decision time.

    PerfectForesight ¶

    Returns the actual prices; the upper-bound benchmark.

    NaiveLastWeek ¶

    Same interval one week earlier, or two weeks earlier where that is missing.

    NoisyForesight ¶

    Actual prices plus Gaussian error, seeded per forecast window for reproducibility.

    PrecomputedForecast ¶

    Forecasts read from a CSV of utc_timestamp and forecast_gbp_per_mwh.

    Backtesting and metrics¶

    openenergy.backtest.engine ¶

    Rolling day-ahead backtest: plan on forecasts, settle at actual prices.

    BacktestConfig dataclass ¶

    lead_hours: how long before each UTC day the plan is fixed (12 = noon the day before).

    information sets which prices a forecast sees. auction (default): every earlier day whose day-ahead auction had published by the decision, as GB's auction publishes each day's prices by 11:00 UTC the day before. decision: only prices for hours that have started by the decision time.

    Site dataclass ¶

    Renewable output (MW, on the price grid) sharing grid with the battery.

    Output is known when planning (perfect generation foresight).

    Carbon dataclass ¶

    Actual grid carbon intensity (gCO2/kWh) for accounting and, with a price, for dispatch.

    planning sets what dispatch sees: last_week uses the same interval a week earlier (two weeks if missing), cut off at the decision time like prices; actual uses the real values and is an upper bound. NESO's archived "forecast" is not used: it is the last forecast before each half-hour, so planning on it the day before would look ahead. Reported money stays market revenue.

    Interval and daily results; skipped maps unsimulated days to the reason.

    System model¶

    openenergy.system.model ¶

    System dispatch: what runs each hour, at what cost, and the price it implies.

    Generator dataclass ¶

    One generator or tranche: available MW and marginal cost (GBP/MWh) per snapshot.

    must_run units produce exactly their available output (historic profiles). emissions_t_per_mwh is tCO2 per MWh of electricity.

    Storage dataclass ¶

    Storage optimised in the dispatch; efficiency is round trip.

    Link dataclass ¶

    A price-taking interconnector to a neighbouring market.

    It imports when GB's price is above price (the neighbour's, GBP/MWh) and exports when below, up to import_mw and export_mw in each snapshot. hurdle (GBP/MWh) is added to imports and taken off exports (losses and trading costs).

    SystemSpec dataclass ¶

    Demand (MW), generators, storage and links on one bus, all on the demand's UTC index.

    SystemResult dataclass ¶

    Dispatch outcome. Power in MW per snapshot; storage is net discharge.

    Unit commitment adds start_price (marginal price including start costs), units_online and starts per committed tranche. With links, links holds each link's net flow (MW, positive into GB).

    by_technology ¶

    by_technology()

    Generation summed by technology, plus storage, net imports and unserved energy.

    price_of ¶

    price_of(kind)

    The marginal price, or (unit commitment only) the price including start costs.

    solve ¶

    solve(spec, backend='auto', commitment=None)

    Dispatch spec at least cost.

    Without storage every hour is independent and the merit order is the exact optimum, so auto uses it; with storage auto uses PyPSA (pip install openenergy[system]). With commitment, thermal units have start-up costs and minimum stable output and days are solved in turn with a lookahead (storage included). The merit order and unit commitment dispatch links as two generators each (see _flatten_links), which gives the same prices as PyPSA's links.

    result_frames ¶

    result_frames(spec, dispatch)

    Generation frame, renewable curtailment and emissions from a T x G dispatch array.

    openenergy.system.fleet ¶

    Build a GB system from the generation mix, fleet data and stated assumptions.

    FleetAssumptions dataclass ¶

    Stated, configurable modelling assumptions; none is fitted to prices.

    Each thermal group is split into tranches of equal size whose efficiencies spread evenly over the fleet average plus or minus the spread (fractions, e.g. 0.04 = 4 pp). Peaking plant (gas turbines and oil engines) is one tranche costed as gas.

    Adjustments dataclass ¶

    Scenario changes to the historic system.

    scale multiplies historic profiles (wind, solar, nuclear, imports, ...) and demand; capacity_mw replaces installed thermal capacity (ccgt, coal, peaking); fuel_price_scale multiplies gas or coal prices; ets_gbp_per_t replaces the ETS price (EU ETS to 2020, UK ETS from 2021); carbon_price_support keeps or removes the GB top-up.

    thermal_generators ¶

    thermal_generators(
    index, inputs, assumptions=None, adjustments=None
)

    CCGT, coal and peaking tranches with short-run marginal cost (GBP/MWh) per period.

    build_system ¶

    build_system(
    mix,
    inputs,
    assumptions=None,
    adjustments=None,
    storage=(),
    voll=DEFAULT_VOLL,
    links=(),
)

    GB on one bus for one calendar year of the generation mix (MW per period).

    Demand is NESO's total generation (scaled by scale['demand']). Fixed profiles keep their (scaled) historic output; wind and solar can be curtailed; thermal plant follows the merit order; links trade with neighbours.

    openenergy.system.merit ¶

    Merit-order dispatch: each period independently, cheapest available plant first.

    merit_order ¶

    merit_order(spec)

    Exact least-cost dispatch for a system without storage.

    Must-run units run at their profile. The rest are stacked by marginal cost; the price is the cost of the last unit needed, or the value of lost load when capacity runs out.
